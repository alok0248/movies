1 · Authentication & Connection
GUIDE How to connect from the app
Base URL

All endpoints are relative to the server origin:

https://newmovies.linkpc.net
Step 1 — Android app identity (Basic Auth)

The user & sync endpoints are protected with HTTP Basic Auth using the access_username / access_password of a registered Android App. The app must be Active. Every request also sends its identity headers so the server can log and rate-limit per app. 

Authorization: Basic base64(access_username:access_password)
X-App-Slug: my-app
X-App-Build: 225
User-Agent: okhttp/4.12.0
Step 2 — User JWT

Login and register return a JWT access + refresh token pair for the end user. Send the access token as a Bearer header on user-scoped calls like profile: 

Authorization: Bearer <access_token>
Step 3 — Streaming endpoints

Streaming endpoints (/api/links/, /ajax/player-sources/) are open (same-origin AJAX + app calls) — no Basic Auth, no JWT. Send Accept: application/json.

Streaming endpoints are intentionally unauthenticated but rate-limited and cached server-side (3 min). If you expose them publicly, consider adding an app check later.
2 · User & Sync API
POST /api/user/sync/ Sync app data ↔ cloud (watchlist, history, settings)

Bidirectional sync between the app and the server. Merges the app's userData into the user's cloud record, pulls web watchlist/history into cloud, and returns the merged payload + subscription. Throttled to one full sync per user per 45 s — within the window it answers from stored cloud data with the same payload shape.

Auth
Authorization: Basic base64(app_user:app_pass)
Content-Type: application/json
Request body
{
  "email": "user@example.com",        // required
  "userData": {                       // optional — app's local data to merge up
    "watchlist": [...],
    "playHistory": [...],
    "settings": {...}
  }
}
Response 200
{
  "status": "success",
  "message": "User data synced successfully",
  "subscription": { "plan": "free", ... },
  "userData": { ...merged cloud data... }
}
Errors: 401 missing/invalid Basic header · 403 wrong credentials · 400 bad JSON / missing email.
POST /api/user/register/ Create account (sends verification email)

Registers a user, hashes the password, and sends a verification email/OTP. User must verify before login.

Request body
{
  "email": "user@example.com",
  "password": "secret123",
  "username": "optional",
  "firstName": "optional"
}
Response 200
{
  "status": "success",
  "message": "...",
  "requiresVerification": true,
  "user": { "userId": "usr_1", "email": "..." }
}
POST /api/user/login/ Authenticate user → JWT pair + cloud data

Authenticates email + password (rate-limited by IP and email), returns JWT tokens, profile, subscription and merged cloud data. Unverified accounts get 403 + requiresVerification.

Request body
{
  "email": "user@example.com",
  "password": "secret123"
}
Response 200
{
  "status": "success",
  "user": {
    "userId": "usr_1", "email": "...",
    "tokens": { "access": "eyJ...", "refresh": "eyJ..." },
    ...profile fields...
  },
  "userData": { ...cloud data... }
}
POST /api/user/refresh/ Renew an expired access token
Request body
{ "refresh": "eyJ..." }
Response 200
{
  "status": "success",
  "tokens": { "access": "eyJ...", "refresh": "eyJ..." }
}
GET /api/user/profile/ Fetch profile + subscription via JWT
Auth
Authorization: Bearer <access_token>
Response 200
{
  "status": "success",
  "user": { "userId": "usr_1", "email": "...", ... },
  "subscription": { "plan": "free", ... }
}
POST /api/user/forgot-password/ Send password-reset OTP to email
Request body
{ "email": "user@example.com" }
Response 200
{ "status": "success", "message": "..." }
Then verify with /api/user/verify-reset-otp/, then set the new password with /api/user/reset-password/.
POST /api/user/verify-reset-otp/ · /api/user/reset-password/ Complete the password reset flow
Request bodies
// verify-reset-otp
{ "email": "user@example.com", "otp": "123456" }

// reset-password
{ "email": "user@example.com", "otp": "123456", "password": "newSecret123" }
Response 200
{ "status": "success" }
POST /api/user/verify-email/ · /api/user/resend-verification/ Email verification (OTP)
Request bodies
// verify-email
{ "email": "user@example.com", "otp": "123456" }

// resend-verification
{ "email": "user@example.com" }
3 · Streaming / Extraction API
GET /api/links/ Direct stream links for native players (ExoPlayer / VLC)

The main extraction endpoint for apps. Queries all upstream servers in parallel, decrypts their payloads, and returns every playable link — raw CDN URL first, plus a server-proxied HLS URL that rewrites manifests so any player can stream even CDNs that block unknown clients. Results cached 3 min.

Query params
ParamDescription
tmdb_idrequiredTMDB id of the movie/series
typerequiredmovie or tv
seasonoptionalSeason number (tv only)
episodeoptionalEpisode number (tv only)
langoptionalFilter sources by language, e.g. hindi
serveroptionalRestrict to one upstream server name
Example request
curl "https://newmovies.linkpc.net/api/links/?tmdb_id=550&type=movie"
Response 200
{
  "success": true,
  "title": "Fight Club",
  "year": "1999",
  "tmdbId": "550",
  "type": "movie",
  "links": [
    {
      "server": "Breach",
      "quality": "1080p",
      "language": "english",
      "type": "hls",
      "url": "https://sun.peakstorm.top/.../index.m3u8",
      "proxy_url": "/proxy/sun.peakstorm.top/.../index.m3u8"
    }
  ]
}
Playback strategy for native players: try url first; if the CDN refuses (403/CORS/IP-bound), play proxy_url. Try each link in order before giving up.
GET /ajax/player-sources/ Extracted sources for the web player (same engine, different shape)

Same extraction engine as /api/links/ but returns the source list shape the web player consumes, and is what the player's server-fallback stage calls when browser extraction fails. Cached 3 min (success) / 60 s (empty).

Query params
tmdb_id, type, season, episode — same as /api/links/
Response 200
{
  "success": true,
  "results": [
    { "name": "Breach", "quality": "1080p", "url": "https://..." }
  ],
  "cached": false
}
GET /ajax/player-episodes/ Episode list for a series season
Query params
tmdb_id, season
Response 200
{ "success": true, "episodes": [ { "episode_number": 1, "name": "...", ... } ] }
GET /ajax/player-subtitles/ · /ajax/stremio-subtitles/ Subtitle tracks for a title
Query params
tmdb_id, type, season, episode, lang (preferred language)
Response 200
{
  "success": true,
  "subtitles": [ { "label": "English", "url": "https://...", "lang": "en" } ]
}
GET /proxy/<host>/<path> Server-side HLS/segment proxy (no scheme in the URL)

Streams any upstream URL through the server and rewrites HLS manifests so segment URLs stay on the proxy. The target has no https:// scheme — the view adds it. Used automatically by proxy_url from /api/links/.

Example
GET /proxy/sun.peakstorm.top/r6/abc/index.m3u8
// → server fetches https://sun.peakstorm.top/r6/abc/index.m3u8
GET /api/player/?tmdb_id=&type= Full web player page (browser embed)
Query params
tmdb_id, type (movie|tv), season, episode, lang
Returns HTML, not JSON — load it in a WebView if the app wants the full web player experience instead of native playback.
GET /direct-player/?tmdb_id=&type= Direct-links browser player page (hls.js + auto fallback)

Standalone browser page that calls /api/links/ and plays the extracted links with hls.js — raw CDN first, then the proxy route, auto-advancing to the next link when one dies. Same params as /api/player/ plus lang.

4 · App Config API
GET /api/android-apps/<app_slug>/ Remote app configuration (identity + access gating)

The app calls its own slug at startup. The server checks the app is active, validates the device identity / build ID against the Android Apps config (allowed endpoint, allowed build ids, ranges like 225-250), logs the access, and returns the app's stored JSON config.

Response 200
{
  "success": true,
  "config": { ...app's stored config JSON... }
}
Blocked requests are logged in Failed Attempts with reason + IP, and 403s are returned.
POST /api/android-apps/<app_slug>/log/ App → server log shipping
Request body
{
  "level": "error",
  "message": "Player failed to start",
  "extra": { ...optional... }
}
